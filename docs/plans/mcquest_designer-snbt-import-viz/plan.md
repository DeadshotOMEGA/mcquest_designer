### Scope

## Implementation

### Approach
## Implementation Approach

**Phase 1: SNBT Library (packages/snbt/ - NEW)**

Create unified SNBT ↔ ProjectSnapshot converter:

1. **Parser Selection: snbt-js**
   - Recent (June 2025), zero dependencies, MIT license
   - Browser-compatible, TypeScript support
   - CRITICAL: FTB Quests uses non-standard SNBT (newlines vs commas)
   - Will need pre-processor to normalize format

2. **Package Structure:**
   ```
   packages/snbt/
   ├── src/
   │   ├── parser.ts          # SNBT text → JS objects
   │   ├── emitter.ts         # JS objects → SNBT text
   │   ├── converter.ts       # SNBT ↔ ProjectSnapshot
   │   ├── lang-handler.ts    # en_us.snbt parsing
   │   └── ftb-adapter.ts     # FTB Quests format normalization
   ├── tests/
   │   ├── parser.test.ts
   │   ├── round-trip.test.ts
   │   └── fixtures/
   └── package.json
   ```

3. **API Design:**
   ```typescript
   // Import
   import { parseSNBT, convertToSnapshot } from '@mcquest/snbt'
   const snbtObj = parseSNBT(chapterText, { format: 'ftb' })
   const snapshot = convertToSnapshot(snbtObj, langData)
   
   // Export
   import { convertFromSnapshot, emitSNBT } from '@mcquest/snbt'
   const snbtObj = convertFromSnapshot(snapshot)
   const snbtText = emitSNBT(snbtObj, { format: 'ftb' })
   ```

**Phase 2: Auto-Layout Visualization**

1. **Algorithm: @dagrejs/dagre**
   - Purpose-built for DAGs (quest chains)
   - 50KB bundle, handles 1000+ nodes
   - Simple integration (~30 lines)
   - Deterministic output

2. **UI Pattern: Auto-layout Flowchart + Modals**
   - Dagre layout for dependency visualization
   - Compact nodes (title + icon)
   - Click → modal with full quest details
   - Visual distinction for optional vs required

3. **Implementation:**
   - "Auto Arrange" button (user-triggered, not continuous)
   - Layout positions saved to ProjectSnapshot
   - Undo/redo integration
   - Per-chapter layout only

**Phase 3: Integration**

1. Import UI: File upload → parse → convert → load
2. Export: Convert → emit → download
3. Testing: Golden round-trip tests with FTB Evolution

### Patterns
## Patterns to Follow

Based on exploration and user preferences:

**SNBT Library (NEW - packages/snbt/)**
- Bidirectional converter: SNBT ↔ ProjectSnapshot
- Browser-based parsing (research existing libraries first)
- Shared type definitions with @mcquest/schema
- Preserve unknown fields in metadata for round-trip
- Validation: return structured errors, don't throw

**Schema Extension**
- Follow existing Zod pattern in packages/schema/src/core.ts
- Add optional metadata fields, don't break existing snapshots
- Use discriminated unions for extensibility (already established pattern)
- Keep validation rules in packages/schema/src/validation/rules.ts

**Visualization - NEW APPROACH**
- **Auto-layout flowchart** using Dagre or ELK layout algorithms
- **Modal-based details**: Click quest card → open modal with full info
- **Dependency-first**: Visualize quest chains and critical paths
- **Visual distinction**: Optional vs required quests (color/border/badge)
- **Compact nodes**: Title + icon only, details on click
- Keep React Flow for rendering (use auto-layout, not manual positioning)

**State Management**
- Continue using Zustand + Immer pattern (established in editor-store.ts)
- Snapshot-based undo/redo (already implemented)
- Selection sync between flowchart and inspector panel

### Data & State
## Data Model Extensions

**ProjectSnapshot Schema Extensions:**

1. **Quest.metadata (optional)**
   - `snbtMetadata?: Record<string, unknown>` - Preserve unknown SNBT fields
   - `ftbQuestsId?: string` - Original hex ID for reference

2. **Chapter.metadata (optional)**
   - `snbtMetadata?: Record<string, unknown>`
   - `images?: ChapterImage[]` - Background decorations (future)

3. **ProjectMetadata extensions:**
   - `importedFrom?: 'snbt' | 'native'`
   - `originalFormat?: { source: string, version: string }`

**Lang File Strategy:**

- Parse en_us.snbt into Map<QuestID, { title, description }>
- Store text inline in Quest objects (existing schema)
- On export, generate lang file from inline text
- Preserve lang keys in metadata for round-trip

### Error Handling
## Error Handling

**Import Strategy: Permissive with Warnings**

- Import all quests, even if validation fails
- Show warnings in validation panel
- Let user manually fix issues post-import
- Don't block import on non-critical errors

**Structured Errors:**
```typescript
interface ImportProblem {
  severity: 'error' | 'warning'
  code: string  // e.g., 'SNBT_PARSE_ERROR', 'UNKNOWN_TASK_TYPE'
  message: string
  entity?: { kind: 'quest' | 'chapter', id?: string, line?: number }
  snbtLocation?: { file: string, line: number }
}

type ImportResult = {
  success: boolean
  snapshot: ProjectSnapshot | null
  problems: ImportProblem[]
}
```

**Common Errors:**
- SNBT parse failures → show line number, excerpt
- Unknown task/reward types → preserve as metadata, warn
- Broken quest references → import anyway, show in validation panel
- Missing lang entries → use quest ID as fallback title

**User Feedback:**
- Progress indicator for large imports
- Clear error messages with actionable guidance
- Link to validation panel after import
