## Implementation

### Approach
## Implementation Approach

**Monorepo structure:**
- pnpm workspaces (no Turborepo overhead)
- Structure:
  ```
  /apps/web/           # Next.js App Router
  /packages/schema/    # Shared Zod schemas
  /packages/export/    # SNBT compiler
  /testdata/ftbq/1.21/ # Golden exports
  ```

**Testing strategy:**
- **Unit/Integration**: Vitest
  - Schema validation tests
  - Export compiler tests (determinism, ID mapping)
  - React component tests (React Testing Library)
- **E2E**: Playwright from start
  - Critical user flows (create project, edit quest, export)
  - Visual regression for graph editor (optional)

**Development workflow:**
1. Tasks tracked in `tasks.yaml` + GitHub Issues
2. Each task is a single PR (when meaningful)
3. CI runs: typecheck, lint, test, build
4. Deploy previews on Vercel for each PR

### Patterns
## Existing Assets & Patterns

**Ready to use:**

   - Complete Zod schema for ProjectSnapshot
   - Task types: ITEM, CHECKBOX
   - Reward types: ITEM, XP, COMMAND
   - Can be moved directly to `packages/schema/src/`

3. `docs/platform_examples/reference_export/`

   - Key differences to handle in compiler:
     - UUIDs → numeric IDs (`1L`, `2L`)
     - Enum case: `SQUARE` → `square`
     - Icon format transformation

**Patterns to follow:**
- Discriminated unions for extensible task/reward types
- Zod schemas as single source of truth
- Snapshot → ExportModel → SNBT pipeline
- Golden exports for regression testing

### Data & State
## Data & State Management

**Editor state (Zustand):**
- Working snapshot (optimistic local state)
- Undo/redo stack (snapshot-based)
- UI state (selection, viewport, panels)
- Sync status (saving, saved, error)

**Server state (TanStack Query):**
- Project list
- Project metadata
- Version history
- Invalidation on mutations

**Autosave strategy:**
- Optimistic local updates (instant feedback)
- Debounced server sync (1-2 seconds)
- Conflict detection (version mismatch warning)
- Offline queue (stretch goal)

**Persistence flow:**
1. User action → update Zustand store (immediate)
2. Debounce timer starts
3. After debounce → POST to server
4. Server validates → saves to Neon
5. TanStack Query cache invalidated

### Error Handling
## Error Handling & Validation UX

**Validation display:**
- **Inline**: Red/yellow indicators on affected nodes
- **Panel**: Collapsible validation panel listing all issues
- Click issue → select affected node

**Error categories:**
- **Blocking (red)**: Quest without title, dependency cycle, missing chapter
- **Warnings (yellow)**: Orphan quests, overlapping nodes, missing description

**Export behavior:**
- Blocking errors prevent export
- Warnings shown but don't block
- Clear error messages with entity references
